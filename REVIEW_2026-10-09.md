# FrameBar and Capturely review

## Changes

- FrameBar publishes each OCR result once instead of updating several observed fields separately. Leaving Roblox or disabling its reader clears every game statistic and its timestamp.
- Display timing probes stop when neither the main panel nor a menu bar refresh reading needs them. Opening settings does not start continuous display timing callbacks.
- Secondary settings are collapsed under Readings & labels, Position & appearance, Shortcut, and Capture & performance. Main readings remain unchanged.
- Capturely rejects out-of-order companion snapshots and clears OCR values without a recent source timestamp. Hardware readings remain usable independently.
- Capturely prunes expired telemetry even when new readings are unavailable and avoids repeatedly deleting an inactive recording request.
- Export checks companion subtitle and telemetry files before replacing a video. Conflicting files block export; identical files are accepted.
- Closing the clip editor cancels pending player setup before it can install a playback observer.

## Validation

FrameBar: 19 tests passed. Capturely: 133 tests passed, including snapshot ordering, missing OCR timestamps, conflicting sidecars, and the existing hardware replay/export test.

These checks do not prove foreground Roblox OCR, simultaneous recording overhead, or overlay exclusion during a real game. The earlier idle FrameBar measurement was 0.05% of one CPU core; the requested sub-1% budget still needs measurement during gameplay and recording.

The instantaneous physical ProMotion refresh rate remains unavailable through the current timing source. Low Power Mode uses Adaptive rather than claiming the selected 120 Hz mode is the current panel rate. Display callback cadence is not proof of physical scanout. Live 1% lows require individual frame timings; OCR samples cannot produce them. Imported frame timing captures support that analysis.

## Features worth considering

1. Quiet, Debug, and Recording profiles: group existing metric, placement, and sampling preferences behind one selection; retain a Custom option.
2. Actionable recording readiness: show a small status only when permissions, missing game stats, or recording errors need attention.
3. Clip/session comparison: compare existing telemetry on demand without adding background polling.
4. Manual recording bookmarks: store a timestamp on a shortcut press for later navigation in the clip editor.

Defer animated dashboards, frequent alerts, and new sensor polling. Live hitch graphs and 1% lows should wait for a genuine per-frame source. Fan, clock, temperature, and VRAM counters need a supported source and measured cost before being promised.

## Follow-up implementation

Quiet, Debug, and Recording profiles are now available in settings. Quiet disables game and desktop FPS readers and uses CPU/RAM overlay readings at 2-second updates. Debug uses 1-second hardware updates with adaptive OCR and adds game CPU/GPU timings, ping, process readings, GPU utilization, and thermal state. Recording uses 2-second updates with adaptive OCR and adds Capturely status; recording still starts in Capturely.

Profiles preserve overlay placement, opacity, visibility, and menu choices. Custom restores the sampling and readings that were active before applying a preset, including after relaunch. Manual changes automatically show Custom when they differ from a preset.

A foreground Roblox readiness line reports missing FPS access or readings and opens the reader controls. Capturely recording status uses the existing telemetry state. No new timers, captures, or polling were introduced. Clip comparisons and bookmarks remain proposals.

Follow-up validation: all 21 FrameBar tests passed, including profile restoration across relaunches and foreground-only readiness states. The installed Release bundle passed strict signature verification.
